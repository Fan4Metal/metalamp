# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

MetalAMP is a Windows-only audio player written in Rust with egui/eframe 0.36 (glow), a replacement for Winamp whose main part is a Winamp-style media library: artists on the left, a grid of albums with their covers, the tracks below, the player bar on top, the playlist on the right, a status line. Playback is Windows' own: Media Foundation decodes (MP3, AAC/M4A, FLAC, WMA, WAV) and WASAPI plays. Priorities: start-up speed, a library that shows at once and stays smooth with thousands of tracks, gapless playback, no external runtime or DLLs. The implementation plan agreed with the user is `local/PLAN.md` (Russian, not in the repository); deferred work is in `TODO.md`. `README.md` / `README.ru.md` are the user-facing docs and must be kept in sync (both languages, cross-linked, formal tone, no imperatives).

The name is written `MetalAMP` wherever people read it (UI, window title, READMEs, installer, `%APPDATA%\MetalAMP`, `%LOCALAPPDATA%\Programs\MetalAMP`, `MetalAMP_<ver>_Setup.exe`) and `metalamp` wherever it is an identifier (Cargo package, `metalamp.exe`, the GitHub repo `Fan4Metal/metalamp`).

## Commands

```
uv run build.py                  # closes a metalamp.exe running from target\, then cargo build --release
cargo build --release            # target\release\metalamp.exe (fat LTO)
cargo test                       # unit tests (<what they cover>)
cargo clippy --all-targets       # must stay warning-free
python tools/make_release.py     # tests, release build, dist\MetalAMP_<ver>_Setup.exe (Inno Setup 6, tools/setup.iss) and _portable.zip
python tools/make_release.py --no-tests --install   # the same, then installs it silently over the installed copy
.\target\release\metalamp.exe --export-icon file.ico   # the app icon for the installer
python tools/icon_png.py         # images\icon.png (the README's icon) from the exe's icon
.\target\release\metalamp.exe --bench scan D:\Music   # a full scan without the index: walk, tags, grouping, index size, folders split into albums
RUST_LOG=metalamp=debug          # debug log (index and scan timings); METALAMP_SCAN_THREADS=n sets the tag readers (default min(cores, 8))
cargo test reads_a_real_file -- --ignored   # with METALAMP_SAMPLE=<an mp3>: lofty reads its tags
```

Releases: pushing a tag `vX.Y.Z` runs `.github/workflows/release.yml`, which runs `make_release.py` and publishes both files; the tag must equal the version in `Cargo.toml`. Creating or pushing a tag publishes a public release, so do it only when the user asks. `tools/setup.iss` installs per user. `.cargo/config.toml` links the CRT statically, so no VCRUNTIME140.dll is needed. These scripts mirror those of disk_flashlight, qview, qrec and metalmd; keep them in step.

Trying a change: `cargo test` and `cargo clippy --all-targets`, then `uv run build.py` and run `target\release\metalamp.exe`; when the change concerns the installed copy (installer, associations, portable mode) or the user runs the program all day, `python tools/make_release.py --no-tests --install` replaces the installed copy silently (it closes the running one first, so its settings are saved).

Toolchain: stable MSVC Rust plus VS 2022 Build Tools. In the Bash tool, `cargo` is not on PATH; prefix commands with `export PATH="$HOME/.cargo/bin:$PATH"`. A running `metalamp.exe` locks the release binary; `build.py` closes it first (WM_CLOSE via `taskkill`, so settings are saved; killed after 3 s). Heredocs containing Rust code break the Bash tool (lifetime apostrophes); write source files with the Write tool or a Python script.

## Architecture

- **`main.rs`**: arguments (`--export-icon`, `--version`, `--help`, `--bench`; the release exe has no console, so the command line modes call `win::attach_parent_console`), the panic hook, `Settings::load`, the first `Scan` (the index read and the folders checked while eframe makes the window, so the first frame shows the library), `NativeOptions` (glow, `with_decorations(false)`, resizable, drag and drop, `DEFAULT_SIZE` 1280×800 points, `MIN_SIZE` 900×560, `centered` only without a saved place), `eframe::run_native`. eframe's `persistence` feature is off: the settings, the window's place among them, are the app's own JSON.
- **`app.rs`**: the eframe `App` (egui 0.36: `fn ui(&mut self, ui, frame)` with `egui::Panel::top/left/bottom(...).show(ui, ...)`, not the older `update(ctx)` / `SidePanel` API; `logic` runs every frame, also while minimised). `App::new` sets the language and `palette::apply`, then, while the window is still hidden, the dark border, `win::round_corners` and the saved place (`win::place`: `SetWindowPlacement` with the saved `rcNormalPosition`, `SW_HIDE` or `SW_SHOWMAXIMIZED`; a maximized window is cloaked (`DWMWA_CLOAK`) until its first maximized frame, `uncloak`, at most 1 s: winit shows a window created maximized before it is painted, a white flash), and hooks the window (`win::hook_window`). `remember_place` reads `GetWindowPlacement` each frame and saves the settings in the background once the window has rested for 1 s; `on_exit`, the end of the session and sleep (`win::Hooked`) save at once.
- **`icon.rs`** draws the app icon procedurally with no dependencies; `build.rs` includes it via `#[path]` to write the `.ico` embedded by `winresource` and `app_icon_{64,128,256}.rgba` into `OUT_DIR`; `main::embedded_icon` and `ui::app_icon` use those, so nothing is rasterised at start-up.
- **`settings.rs`**: JSON through serde as metalmd's (`%APPDATA%\MetalAMP\config\settings.json`; `#[serde(default)]`, so older files read with defaults and unknown fields are ignored; written as `.tmp` and renamed; `save_in_background` numbers the saves so the last asked for wins), or `metalamp.json` next to the exe when that file exists and can be written (portable mode, `settings::location`, decided once per run; the portable zip ships it empty). About shows which. `data_dir` is that folder: the library index, the playlist and the covers go there too. The window's place is `WindowPlace { normal, maximized }`: Windows' restored rectangle in pixels (work-area coordinates, kept also while maximized), so a window closed maximized comes back maximized and restores to its own size, not the screen's.
- **`update.rs`**: the opt-in update check (off by default, once a day at start-up, "Check now" in About): `win::https_get` (WinHTTP) asks `api.github.com/repos/…/releases/latest`, `tag_name` is picked out of the JSON by hand, a newer release shows `ui::update_button` beside About, opening the release page built from `CARGO_PKG_REPOSITORY`. `cargo test update -- --ignored` asks GitHub for real.
- **`caption.rs`**: `hwnd`, and `set_dark` (`DWMWA_USE_IMMERSIVE_DARK_MODE`) once while the window is hidden; the theme never changes, so the family's `refresh` is left out.
- **`frameless.rs`** (metalmpv's without fullscreen): the window has no Windows frame but stays resizable for Windows (`WS_SIZEBOX`/`WS_MAXIMIZEBOX`: Aero Snap, Win+arrows, maximizing to the work area). No window region (qrec's way loses the DWM shadow): `win::round_corners` asks DWM for rounded corners (Windows 11; square on Windows 10). Strips along the edges (5 pt, corners 14 pt) start `ViewportCommand::BeginResize`; `drag_area` (`StartDrag`) leaves those strips alone, since a widget registered later covers an earlier one.
- **`palette.rs`**: every colour (always dark, Winamp's media library as the model) and `apply` for egui's visuals; the accent is the amber of the icon's bolt.
- **`ui/title.rs`**: the title row (metalmpv's): the icon, the title, About and a newer release's button, minimise/maximise/close 46 points wide (`TitleCmd`); its free area drags the window, a double click maximizes.
- **`win.rs`**: `error_box` (user32 `MessageBoxW` declared by hand), `attach_parent_console`, `shell_open` (`ShellExecuteW`; eframe's `links` feature is off), `https_get`, `show_in_folder` (`SHOpenFolderAndSelectItems` on a thread with COM, declared by hand; `explorer /select` leaves the window behind the app's); from metalmpv `round_corners`, `cloak`, `placement`/`place`, `double_click_time` (egui assumes 0.3 s), and `hook_window`: a subclass (`SetWindowSubclass`) queuing media keys (`WM_KEYDOWN` with `VK_MEDIA_*`, which egui drops, and `WM_APPCOMMAND` from headsets and remotes), `WM_QUERYENDSESSION` and `PBT_APMSUSPEND` for `take_hooked`.
- **`library/`**: the media library. `Track` (path, size, mtime, title, artist, album artist, album, year, track, disc, genre, duration, bit rate, sample rate, channels, `has_cover`); `Library::new` groups tracks into albums by lower-case filed artist (album artist, else artist) and album title, **whatever their years** (Winamp's grouping: a compilation's tracks carry the years of their first release; the album's year is its earliest), tracks by disc, number, file name; artists by `format::natural_cmp` (case-blind, digits by value), their albums by year. `search` holds each track's lower-case words, `matches` needs every word of the query. `tags.rs` reads with lofty (`Probe` with properties and pictures: the whole ID3v2 tag is read anyway) and fills what the tag lacks from `Artist\(Year) Album\NN - Title.ext` (`split_number`, `split_year`). `index.rs`: `library.json` next to the settings, compact JSON with a `version`, ~350 bytes a track (1.7 MB for 4942). `scan.rs`: one thread per scan (`Scan`, dropped = cancelled): the index first (`ScanMsg::Loaded`), then `walk` (walkdir, `filetypes::is_audio`), unchanged files (same size and mtime) taken from the index, the rest read on a rayon pool of min(cores, 8) threads in chunks of 500 with a `Loaded` library after each (the first scan fills the view as it goes), progress at most 10 times a second, then grouped, the index saved when anything was read or removed, `ScanMsg::Done`. The UI only swaps the `Arc<Library>`.
  Measured on D:\Music (4942 MP3, 50 GB, a SATA HDD): walk 20 ms; tags cold 49 s (10 ms a file; 8 threads 7.3 ms a file against 11 ms for one on cold folders of the same disk), warm 161 ms; grouping 6-10 ms; the index read and grouped at start 12 ms, a rescan finding nothing changed 26 ms.
- **`ui/library.rs`**: the library view, as Winamp's: a bar (search field, Ctrl+F, Esc clears; albums as covers or as a table; read the folders again, F5; the folders' menu: remove one, add one), the artists on the left with "All" first, the albums at the top right, the tracks under them; strips between the panes move the borders (`artists_width`, `tracks_height`). The choice of artist and album is kept by name (lower-case name, `Album::key`), so it survives a new scan. A `View` (the artists, albums and tracks the search and the choice leave, each sorted by its table's column) is built only when the library's `Arc`, the search, the choice or a sort changed: 0.0-0.5 ms for 4942 tracks, shown in the status line as Winamp shows its query's time. Choosing an artist narrows the albums, an album the tracks; the arrow keys move in the pane last clicked (`Pane`) when no text field has the focus; Enter or a double click plays (an artist: its tracks once the view for it is built, `play_shown`; an album: its tracks; a track: the whole table from it, Winamp's way); the right button opens a menu (Play, Add to the playlist, Show in folder). The panes report `LibraryAction`s to the app. The album grid has the album table's header over it, which sorts it; cells of 168×200 points with a 152-point cover, only the rows in sight painted.
- **`ui/table.rs`**: the tables: `header_row` (a click sorts by a column, again the other way, `Sort`; a column's right edge dragged changes its width), rows of 20 points painted only where seen (`ScrollArea::show_viewport`), stripes, selection, the row playing in the accent, right-aligned text cut at its end when it does not fit; `click_select` (Ctrl toggles, Shift ranges from the anchor) and `key_move` (arrows, Page Up/Down, Home/End).
- **`covers.rs`**: album covers: a 256-pixel JPEG thumbnail per album in `covers\` next to the settings, named by an FNV-1a hash of the album's key and its first file's path and time (a changed file gets a new one); made from the folder's picture (`folder`, `cover`, `front`, `albumart`, any case: one small file, the quickest on a hard disk), else the first tagged track's front cover (lofty); an album without either gets an empty `.none` file. One worker thread, the album asked for last first (the cells in sight ask every frame); at most 256 textures (64 MB), the ones shown longest ago dropped. JPEG and PNG only, decoded within limits (8192 px, 256 MB).
- **`filetypes.rs`**: the extensions Media Foundation plays (`mp3`, `m4a`, `aac`, `flac`, `wma`, `wav`), any case.
- **`format.rs`**: track times, the library's length as Winamp's status line (`15 days+16:40:20` / `15 дн.+16:40:20`), sizes in binary units (`49.02 GB` / `49,02 ГБ`), `natural_cmp`.
- **`bench.rs`**: `--bench scan <folder>…` (see Commands).
- **`ui/status.rs`**: the status line: tracks, length, size; the scan's progress on the right.
- **`ui/`**: `app_icon`, toolbar buttons with a painted icon (`icon_button`), `about_button`, `update_button`, `close_cross`, `double_clicked`; `App::raw_input_hook` holds the right button's press back until it is let go and gives both to egui at the release, so a context menu opens even when the mouse moved while the button was down (egui's click allows 6 points and 0.8 s; qview's way); `ui/about.rs` the About modal; `ui/start.rs` the start screen while the library has no folder (icon, name, version, one line on how to begin).
- **`ui/icons.rs`**: the painted icons shared by the family (the default fonts lack many symbols), on a 14-point grid with 1.3-point lines; `Shuffle`, `Repeat`, `RepeatOne` (from metalmpv) and `Refresh` (two arcs with heads, unlike the single arc of the turns) were added here and copied back to the skill's catalogue. A new icon is added there on the same grid and checked next to the others with `cargo run --example icons`, not drawn ad hoc in a panel.
- **`icon.rs`** (the drawing): an electric guitar (single-cutaway body in cherry red with cream binding, rosewood neck, black headstock with a light edge so it shows on a dark taskbar) lying from the bottom left to the top right over a yellow lightning bolt, lit from the top with a soft shadow; layers of 24 px and less drop the strings, frets, knobs, tuners and binding and get a wider neck. `sample(x, y, px)` smooths edges over one pixel of the layer (signed distance fields: circles, a smooth union, a polygon for the bolt).


## Conventions

- Every user-visible string goes through `tr!("English", "Русский")` (`i18n.rs`); the language follows the Windows UI language (`i18n::system_lang`, `GetUserDefaultUILanguage`) unless chosen in About (`i18n::LangChoice`, `system`/`en`/`ru` in the settings; applied in `App::new` before any text is made and at once when changed). Strings are built every frame, so nothing caches translated text. Log messages, CLI output and technical errors stay English.
- Persisted state (`settings.json`): `language` (`system`/`en`/`ru`), `check_updates`, `last_update_check` (Unix seconds), `window` (`normal`: `[left, top, right, bottom]` pixels, `maximized`), `album_view` (`grid`/`table`), `artists_width`, `tracks_height` (points), `columns` (each table's widths by name: `artists`, `albums`, `tracks`), `sorts` (each table's `{column, descending}`; none: the library's order), `library_folders` (paths; Ctrl+Shift+O or a folder dropped on the window adds one, a folder inside a listed one is not added, one holding listed ones replaces them; F5 rescans). The library index (`library.json`) sits next to `settings.json`.
- The version comes from `Cargo.toml` (`main::VERSION`, shown in About). Between releases it is the next version with `-dev`, the last number raised by one (after `0.1.0`, `0.1.1-dev`), and `build.rs` appends `git describe --tags --always` (`0.1.1-dev (v0.1.0-2-g4bd494d)`); a release version is shown as is. Release: drop `-dev`, commit `Version X.Y.Z`, tag `vX.Y.Z` (release.yml checks the tag against `Cargo.toml`), then set the next `-dev` version (`X.Y.(Z+1)-dev`).
- The release profile has `panic = "abort"` and no console: a panic shows a message box (`main::install_panic_hook`) and ends the program. `f32::clamp` panics when its bounds cross; sizes read from files may be 0.
- Commits in this repository end with a `Co-Authored-By:` trailer naming the Claude model doing the work, e.g. `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` (the user's decision; it overrides the global "no Co-Authored-By" rule for this repo only).
- GUI checks: the OpenGL client area cannot be captured with `PrintWindow` on an NVIDIA machine (the caption can, from a DPI-aware process); keys can be posted with `PostMessage(WM_KEYDOWN/WM_KEYUP)`, but each posted key reaches egui three times (seen in a trace of `raw_input_hook`: an arrow moved three rows), and posted `WM_CHAR` and Ctrl do not reach it (winit reads the keyboard's state), so typing and counts of steps are checked by the user; the screen can be captured with `CopyFromScreen` from a DPI-aware process (this machine's OpenGL area is captured). A launched window takes the focus: warn the user before launching test windows and before any simulated global mouse or keyboard input, and close test windows with `taskkill /PID` (WM_CLOSE, which saves the settings).
