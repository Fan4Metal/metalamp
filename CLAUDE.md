# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

MetalAMP is a Windows-only audio player written in Rust with egui/eframe 0.36 (glow), whose main part is a media library: artists on the left, a grid of albums with their covers, the tracks below, the player bar on top, the playlist on the right, a status line. Playback is Windows' own: Media Foundation decodes (MP3, AAC/M4A, FLAC, WMA, WAV) and WASAPI plays. Priorities: start-up speed, a library that shows at once and stays smooth with thousands of tracks, gapless playback, no external runtime or DLLs. The implementation plan agreed with the user is `local/PLAN.md` (Russian, not in the repository); deferred work and the tasks of reviews are in `local/TODO.md` (not in the repository either). `README.md` / `README.ru.md` are the user-facing docs and must be kept in sync (both languages, cross-linked, formal tone, no imperatives).

The name is written `MetalAMP` wherever people read it (UI, window title, READMEs, installer, `%APPDATA%\MetalAMP`, `%LOCALAPPDATA%\Programs\MetalAMP`, `MetalAMP_<ver>_Setup.exe`) and `metalamp` wherever it is an identifier (Cargo package, `metalamp.exe`, the GitHub repo `Fan4Metal/metalamp`).

## Commands

```
uv run build.py                  # closes a metalamp.exe running from target\, then cargo build --release
cargo build --release            # target\release\metalamp.exe (fat LTO)
cargo test                       # unit tests (<what they cover>)
cargo clippy --all-targets       # must stay warning-free
python tools/make_release.py     # tests, release build, dist\MetalAMP_<ver>_Setup.exe (Inno Setup 6, tools/setup.iss) and _portable.zip
python tools/make_release.py --no-tests --install   # the same, then installs it silently over the installed copy
.\target\release\metalamp.exe --export-icon file.ico   # the app icon for the installer
python tools/icon_png.py         # images\icon.png (the README's icon) from the exe's icon
python tools/notices.py          # licenses\THIRD_PARTY_NOTICES.txt after the dependencies change (a test fails until then)
.\target\release\metalamp.exe --bench scan D:\Music   # a full scan without the index: walk, tags, grouping, index size, folders split into albums
.\target\release\metalamp.exe --bench gapless a.mp3 b.mp3   # what the decoder gives (trimmed) against each file's LAME tag
.\target\release\metalamp.exe --bench loudness a.mp3   # EBU R128 loudness, peak and the normalisation gain, with the time taken (ffmpeg -af ebur128 agrees to 0.1 LU)
RUST_LOG=metalamp=debug          # debug log (index and scan timings); METALAMP_SCAN_THREADS=n sets the tag readers (default min(cores, 8))
cargo test reads_a_real_file -- --ignored   # with METALAMP_SAMPLE=<an mp3>: lofty reads its tags
cargo test decoder_opens_sample -- --ignored   # METALAMP_SAMPLE: Media Foundation decodes it and seeks
cargo test engine_goes_on_without_a_gap -- --ignored --nocapture   # METALAMP_SAMPLE and the next file of its folder: plays ~3 s quietly on the default device
cargo test play_while_paused_plays -- --ignored --nocapture   # METALAMP_SAMPLE: a Play after a Pause plays (~2 s quietly)
```

Releases: pushing a tag `vX.Y.Z` runs `.github/workflows/release.yml`, which runs `make_release.py` and publishes both files; the tag must equal the version in `Cargo.toml`. Creating or pushing a tag publishes a public release, so do it only when the user asks. `tools/setup.iss` installs per user; its uninstaller closes a copy running from the installed folder (PowerShell's `CloseMainWindow`, so the settings are saved) and, unless silent, asks whether to delete `%APPDATA%\MetalAMP` (qrec's way). `.cargo/config.toml` links the CRT statically, so no VCRUNTIME140.dll is needed. These scripts mirror those of disk_flashlight, qview, qrec and metalmd; keep them in step.

Trying a change: `cargo test` and `cargo clippy --all-targets`, then `uv run build.py` and run `target\release\metalamp.exe`; a test that plays sound should lower `volume` in `settings.json` first and put it back (it is the user's music on the user's speakers). When the change concerns the installed copy (installer, associations, portable mode) or the user runs the program all day, `python tools/make_release.py --no-tests --install` replaces the installed copy silently (it closes the running one first, so its settings are saved).

Toolchain: stable MSVC Rust plus VS 2022 Build Tools. In the Bash tool, `cargo` is not on PATH; prefix commands with `export PATH="$HOME/.cargo/bin:$PATH"`. A running `metalamp.exe` locks the release binary; `build.py` closes it first (WM_CLOSE posted to its visible windows, `post_close`, so settings are saved; `taskkill` without /F skipped a minimized window; killed after 3 s; `make_release.py` likewise). Heredocs containing Rust code break the Bash tool (lifetime apostrophes); write source files with the Write tool or a Python script.

## Architecture

- **`main.rs`**: arguments (`--export-icon`, `--register`/`--unregister` (named in the language of Windows), `--version`, `--help`, `--bench`, otherwise files: `normalize` fixes Explorer's `C:"` and makes them absolute; `instance::forward` hands them to a running copy; the release exe has no console, so the command line modes call `win::attach_parent_console`), the panic hook, `Settings::load`, the first `Scan` (the index read and the folders checked while eframe makes the window, so the first frame shows the library), `NativeOptions` (glow, `with_decorations(false)`, resizable, drag and drop, `DEFAULT_SIZE` 1280×800 points, `MIN_SIZE` 900×560, `centered` only without a saved place), `eframe::run_native`. eframe's `persistence` feature is off: the settings, the window's place among them, are the app's own JSON.
- **`app.rs`**: the eframe `App` (egui 0.36: `fn ui(&mut self, ui, frame)` with `egui::Panel::top/left/bottom(...).show(ui, ...)`, not the older `update(ctx)` / `SidePanel` API; `logic` runs every frame, also while minimised). `App::new` sets the language, `palette::apply` and egui's options (no keyboard zoom, Windows' double-click time, `line_scroll_speed` 100: a wheel notch scrolls 100 points, not egui's 40, as qview and metalmd), then, while the window is still hidden, the dark border, `win::round_corners` and the saved place (`win::place`: `SetWindowPlacement` with the saved `rcNormalPosition`, `SW_HIDE` or `SW_SHOWMAXIMIZED`; a maximized window is cloaked (`DWMWA_CLOAK`) until its first maximized frame, `uncloak`, at most 1 s: winit shows a window created maximized before it is painted, a white flash), and hooks the window (`win::hook_window`). `remember_place` reads `GetWindowPlacement` each frame and saves the settings in the background once the window has rested for 1 s; `on_exit`, the end of the session and sleep (`win::Hooked`) save at once.
- **`icon.rs`** draws the app icon procedurally with no dependencies (`ico` of BMP layers for `--export-icon`, `ico_of`, `bmp`); `build.rs` includes it via `#[path]` to write the `.ico` embedded by `winresource` (its 256 px layer as PNG through the `png` build dependency, as qview's, also for the file type icons: resources 101+) and `app_icon_{64,128,256}.rgba` into `OUT_DIR`; `main::embedded_icon` and `ui::app_icon` use those, so nothing is rasterised at start-up.
- **`guard.rs`**: `catch(path, read)`, `catch_unwind` with a thread-local flag that the panic hook reads to only log (see Conventions).
- **`kept.rs`**: `Kept`, the writes of a file kept next to the settings (the settings, `library.json`, `playlist.m3u8`, `loudness.json`, `stats.json`): numbered when asked for (`ask`; a scan takes its number when it starts), written to `<file>.tmp` and renamed, one writer at a time, never an older write over a newer one.
- **`settings.rs`**: JSON through serde as metalmd's (`%APPDATA%\MetalAMP\config\settings.json`; `#[serde(default)]`, so older files read with defaults and unknown fields are ignored; `from_json` reads each field on its own, so a value that cannot be read (a later version's theme, a typo) costs only that field, and a file that is not JSON is kept as `settings.json.bad`; written as `.tmp` and renamed; `save_in_background` numbers the saves so the last asked for wins), or `metalamp.json` next to the exe when that file exists and can be written (portable mode, `settings::location`, decided once per run; the portable zip ships it empty). About shows which. `data_dir` is that folder: the library index, the playlist and the covers go there too. The window's place is `WindowPlace { normal, maximized }`: Windows' restored rectangle in pixels (work-area coordinates, kept also while maximized), so a window closed maximized comes back maximized and restores to its own size, not the screen's.
- **`update.rs`**: the opt-in update check (off by default, once a day at start-up, "Check now" in the settings window): `win::https_get` (WinHTTP) asks `api.github.com/repos/…/releases/latest`, `tag_name` is picked out of the JSON by hand, a newer release shows `ui::update_button` in the title row, opening the release page built from `CARGO_PKG_REPOSITORY`. `cargo test update -- --ignored` asks GitHub for real.
- **`caption.rs`**: `hwnd`, and `set_dark` (`DWMWA_USE_IMMERSIVE_DARK_MODE`) while the window is hidden and whenever the theme changes between dark and light.
- **`frameless.rs`** (metalmpv's without fullscreen): the window has no Windows frame but stays resizable for Windows (`WS_SIZEBOX`/`WS_MAXIMIZEBOX`: Aero Snap, Win+arrows, maximizing to the work area). No window region (qrec's way loses the DWM shadow): `win::round_corners` asks DWM for rounded corners (Windows 11; square on Windows 10). Strips along the edges (5 pt, corners 14 pt) start `ViewportCommand::BeginResize`; `drag_area` (`StartDrag`) leaves those strips alone (`inside_edges`), since a widget registered later covers an earlier one; so does the playlist's scroll area (its rows sense drags, to move entries, and took the right edge, as its scroll bar would; a widget sensing clicks only lets the drag through to the strip).
- **`palette.rs`**: every colour, as functions of the palette in use (`palette::text()`, not constants): `Theme` (listed from the darkest to the lightest by the window's mean luminance, an order a test holds: black; midnight blue; dark graphite, the default; steel (black lists with steel-blue text (`list_text`), light grey text around them and on the column headers (`header_text`), a steel frame, settings cards darker than it and a dark column of pages (`sidebar_bg`), which a theme may leave out to follow `text`, `text_weak` and `title_bg`; the test checks the weak text on the cards and panels and the headers too); dimmed (softer cool greys); sepia (warm paper); light) and `Accent` (amber, the default, the icon's bolt; metalmpv's blue, teal, green, orange, red, pink, purple, graphite; and `Custom(0xRRGGBB)`, the last swatch, a colour wheel opening metalmpv's picker: saturation and brightness in a square, the hue in a bar, a field for the code in HEX, RGB or HSL (`ColourText`, switched by a click on its name; `Accent::typed` reads any of them, tested) and R, G, B fields; kept by name, `amber` or `#12AB9F`, an unknown one read as the default), both settings (`theme`, `accent`) on the General page (a list and metalmpv's round swatches, `accents`), and two `Tint`s (all four in `Look`, `Settings::look`): `selection` (the selected rows' ground) and `playing` (the track playing's text), each mixed from the accent, the default; from grey, slate, blue, teal or purple, mixed alike whatever the accent; for `playing` also `Bright`, the theme's `text_bright` (`Tint::SELECTION`/`PLAYING` are the swatches offered); or `Custom`, the user's colour as it is, through the same picker (`tints`, `own_colour`; swatches showing each shade as the lists would, outlined); amber's mixed ground is a brown the user found dirty; `selected_text` is the theme's bright text unless an own colour needs black or white, tested for every theme), applied at once (`palette::set` into a `RwLock`, `apply`, `caption::set_dark`); `Palette::of` mixes every accent's shades alike from its colour (the selection, the track playing, the spectrum; on a light ground a shade deeper; amber once kept a slate selection and a light blue track, which the user found out of place with it), `on_accent` (dark or white by luminance) for the Play button's glyph; a test checks every pair's contrasts (WCAG); and `apply` for egui's visuals (egui's dark or light as the base), scroll bars `ScrollStyle::thin` (always seen, 6 points taken: the lists lay their rows out in the viewport's width, not their rect's); the selection and the track playing in the lists are shades of the accent; the controls (the Play button, the seek bar, the toggles) are in the accent too (amber, the icon's bolt, by default).
- **`ui/title.rs`**: the title row (metalmpv's): the icon (a click opens About, as F1; the family's "i" button is left out, the row is bare), the title, a newer release's button, minimise/maximise/close 46 points wide (`TitleCmd`), left of them the mini player's (`Mini`, metalmpv's icon) and "over the others" (`Pin`, lit in the accent while on, `title::Modes`) buttons, 36 points; its free area drags the window, a double click maximizes.
- **`win.rs`**: `error_box` (user32 `MessageBoxW` declared by hand), `attach_parent_console`, `shell_open` (`ShellExecuteW`; eframe's `links` feature is off), `https_get`, `show_in_folder` (`SHOpenFolderAndSelectItems` on a thread with COM, declared by hand; `explorer /select` leaves the window behind the app's); from metalmpv `round_corners`, `cloak`, `placement`/`place`, `double_click_time` (egui assumes 0.3 s), and `hook_window`: a subclass (`SetWindowSubclass`) queuing media keys (`WM_KEYDOWN` with `VK_MEDIA_*`, which egui drops, and `WM_APPCOMMAND` from headsets and remotes), `WM_QUERYENDSESSION` and `PBT_APMSUSPEND` for `take_hooked`.
- **`library/`**: the media library. `Track` (path, size, mtime, title, artist, album artist, album, year, track, disc, genre, duration, bit rate, sample rate, channels, `has_cover`, `added`: when the scan first found it, kept when read again (`read_tracks`); an index from before it takes the file's time (`index::load`), so does a library's first scan); `Library::new` groups tracks into albums by lower-case filed artist (`Track::filed_artist`: album artist, else artist; for a folder's album none of whose tracks has an album artist, `filed_without_album_artist` (worked out each time, `Track::filed`, not kept): `VARIOUS_ARTISTS` for a compilation (3+ tracks, 3+ main artists, none over half; `main_artist` cuts "feat.", "&", "," and the like), the artist for an album with guests (one main artist under several names); tested; D:\Music, all tagged with album artists, keeps its 329 albums) and album title, **whatever their years** (a compilation's tracks carry the years of their first release; the album's year is its earliest), except editions in folders of their own (`editions`: folders whose earliest years differ and whose disc numbers overlap, a Greatest Hits of 1990 and of 2005, are two albums, the key followed by the year; CD1/CD2 folders of other discs and folders without years stay one; D:\Music keeps its 405 albums), tracks by disc, number, file name; artists by `format::natural_cmp` (case-blind, digits by value), their albums by year. `search` holds each track's lower-case words, `matches` needs every word of the query. `tags.rs` reads with lofty (`tags::open`, also for the file info and the covers: properties and pictures, the whole ID3v2 tag is read anyway; an MP3 with several ID3v2 tags one after another (`mp3gap::leading_tags`) is read through `Holed`, a view of the file without the tags after the first: lofty puts their frames over the first's (lofty-rs#87), while players and taggers read and write only the first, so a stale tag behind a corrected one split an album, as Within Temptation's The Unforgiving with three bonus tracks) and fills what the tag lacks from `Artist\(Year) Album\NN - Title.ext` (`split_number`, `split_year`). `index.rs`: `library.json` next to the settings, compact JSON with a `version` (2; an index of a version in `READ_AGAIN`, 1, is shown while every file is read again, the parts read not shown meanwhile), ~350 bytes a track (1.7 MB for 4942). `scan.rs`: one thread per scan (`Scan`, dropped = cancelled): the index first (`ScanMsg::Loaded`), then `walk` (walkdir, `filetypes::is_audio`), unchanged files (same size and mtime) taken from the index (a folder or file the walk could not read, a disk not plugged in, keeps the index's tracks: `Walked::unreadable`; a file that cannot be opened while its tags are read keeps what was known of it, or is left out, and is read again next time), the rest read on a rayon pool of min(cores, 8) threads in chunks of 500 with a `Loaded` library after each (the first scan fills the view as it goes), progress at most 10 times a second, then grouped, the index saved when anything was read or removed (and after each chunk of a long scan, so a scan cut short by the program's end goes on from there), `ScanMsg::Done`. The UI only swaps the `Arc<Library>`.
  Measured on D:\Music (4942 MP3, 50 GB, a SATA HDD): walk 20 ms; tags cold 49 s (10 ms a file; 8 threads 7.3 ms a file against 11 ms for one on cold folders of the same disk), warm 161 ms; grouping 6-10 ms; the index read and grouped at start 12 ms, a rescan finding nothing changed 26 ms.
- **`ui/library.rs`**: the library view: a bar (search field, Ctrl+F, Esc clears; albums as covers or as a table; the playlist shown or hidden; read the folders again, Ctrl+R; the folders' menu: remove one, add one, read all the tags again (`LibraryAction::ReadAll`, `Scan::start`'s `read_all`: the library shown meanwhile, as for an index of an older version)), the artists on the left with "All" first, under them the view's row (`view_row`, `VIEW_ROW` 26 points: the view's icon (`view_icon`) in the accent while a view narrows the library, else the library's `Library` icon, weak; its name; a menu of the whole library and the views, each with its icon and Ctrl+digit (`view_item`), "New view…", "Edit…"; `choose_view` for Ctrl+1…9, handled by the app), the albums at the top right, the tracks under them; strips between the panes move the borders (`artists_width`, `tracks_height`). A view's filter is the first thing `build` applies (`shown`), before the search, so every pane, the counts and the status line (prefixed with the view's name) follow it; it is part of `ViewKey`. The choice of artist and album is kept by name (lower-case name, `Album::key`), so it survives a new scan. A `View` (the artists, albums and tracks the search and the choice leave, each sorted by its table's column) is built only when the library's `Arc`, the search, the choice or a sort changed: 0.0-0.5 ms for 4942 tracks, shown in the status line with the counts. Choosing an artist narrows the albums, an album the tracks; the arrow keys move in the pane last clicked (`Pane`) when no text field has the focus; letters typed with the pointer over the artists' pane (`pointer_over_artists`, decided by the app before its keys, which then leave the letters alone) go to the first artist starting with them, typed within 1 s of each other they add up, one letter again goes on to the next (`TypeAhead`, `type_ahead`, as Windows' lists; egui's text events, so Cyrillic too); Enter or a double click plays (an artist: its tracks once the view for it is built, `play_shown`; an album: its tracks; a track: the whole table from it); the right button opens a menu (`context_menu`: Play, Play next (`LibraryAction::PlayNext`, `Player::play_next`: inserted after the current entry, `Queue::insert` with `next`; played if nothing plays), Add to the playlist, Show in folder; `extras`: on an album "Go to artist", on a track "Go to album", "Go to artist", the Rating submenu (`MenuChoice::Rating`, `Rate(n)`; `stars`), Edit tags (`LibraryAction::EditTags`; `edit_tags_label`, shared with the playlist) and File info; the tracks' table has the rating, plays, last play's day and the day added (`format::date`, local, by `win::local_date`) after the bit rate, sortable). "Go to" (`LibraryAction::GoTo`, also from the playlist's menu, `PlaylistAction::GoTo`, for an entry the library holds) is `LibraryView::go_to`: the album's artist chosen (and the album), a search or a view that would hide the track (else the album or the artist, `go_to_target`, tested) given up, and once the view is built (`finish_going`) the rows scrolled into sight and the track selected; the keys go back to the library's panes. The panes report `LibraryAction`s to the app. The album grid has the album table's header over it, which sorts it; cells of `cover_size` + 16 × `cover_size` + 48 points (the cover 96–256, `MIN_COVER`/`MAX_COVER`, 152 by default; Ctrl and the wheel over the grid step it by 16, and the right button on the bar's covers button opens `COVER_PRESETS` (112/152/208/256) and a slider; the thumbnails are 256 px, so the largest covers are a little upscaled on a scaled display), only the rows in sight painted.
- **`library/filter.rs`**: the library's views (Winamp's smart views): `Filter { name, icon, any, rules }` (`ViewIcon`: note, film, bolt, heart, star, clock, disc, mic, headphones, globe, folder; an unknown name reads as the note, `icon_or_note`), a `Rule { field, op, value, to }` per line (`Field`: genre, artist (the track's or the album's), album artist, album, title, year, folder, bit rate, length in minutes, days since the track came into the library (`Track::added_or_mtime`), plays, days since the last play (none: never played), rating (from `stats::Stat`, which `Compiled::matches` takes with the track), a cover in the tag; `Op` by the field's `Kind`: text (contains, is, starts with, empty and their negatives, compared in `search_form`), number (is, less, greater, between; a number the file lacks holds only for "is not"), folder (inside: the file's folder or one above it), flag), `is_complete`, `compile(now)` → `Compiled::matches(&Track)` (the negatives as inverted positives; no rules: every track). Kept in the settings (`views`, `view` the name in use; `Settings::current_view`). Tested.
- **`ui/view_editor.rs`**: the view editor (a modal of 660 points, `METALAMP_VIEW_EDITOR=1` opens it at start for GUI checks): the name, the icon (`icon_choice`: a row of the eleven, the chosen one in the accent on the selection's ground), "all the rules / any rule", a row per rule (field and operation combo boxes, the value as the field takes it: a text with a menu of the library's values (`Suggestions`: genres, artists, album artists, albums, the folders), a number (red while not one; two for "between"), a folder with a browse button), a minus per row, "+ Add a rule" (at most 12), a live line with the artists, albums and tracks the draft leaves, Delete (an existing view), Cancel, OK (disabled while the name is empty or taken or a rule incomplete; Enter when no field has the focus; a new view is switched to). Esc closes, a click outside does not (a draft is not lost by a slip).
- **`ui/mini.rs`**: the mini player (metalmpv's): the window a square of the cover heard (`Cover`: the track's file read on a thread, `covers::large`, the folder's picture else the tag's, at most 1000 px, the cover before kept meanwhile; a picture not square cut to its middle), the app icon on the bar's ground without one; over it while the pointer moved within 2 s, rests on them, a button is down or nothing plays (`METALAMP_MINI_CONTROLS=1` always, GUI checks): the title and the artist and the way back (`Icon::Mini`, `BarCmd::Whole`) along the top, the seek bar, Previous, Play/Pause, Next, the speaker and the volume along the bottom (`player_bar`'s `seek_bar`, `mute_button`, `volume_slider`); the cover drags the window, a double click goes back. `App::apply_modes` makes the window it: always on top whatever `on_top` says, the whole window's placement kept in `window` (`remember_place` keeps `mini_rect` instead meanwhile), `win::set_mini` (the least side, 200 points, and the square kept while the edges are dragged: the subclass's `WM_GETMINMAXINFO` after winit's and `WM_SIZING`, `win::squared`, tested; moved, it is drawn to the work area's edges within 16 px at 96 dpi: `WM_MOVING`, `win::snap` from where the move began and the pointer's way (`MOVE_START`, `WM_ENTERSIZEMOVE`), `win::snapped_to_edges`, metalmpv's, tested), maximize disabled (`EnableButtons`), `win::set_rect` to `mini_rect` (on a monitor) else 300 points in the work area's corner, 16 from its edges; back, `win::show_placed` with `window`, and until the window has grown (`App::growing`, at most 1 s) only the ground is painted: the playlist and the library's panes laid out in the mini player's size took it as their own width. Started in it, the whole window is placed hidden and not maximized and the mini player put over it before it shows. A modal, the file info, the equalizer's window, Ctrl+F or Alt+E (the playlist shown) leave it; `Esc` too. The title row and the bar, the playlist, the status line and the library are not drawn; the wheel over it steps the volume.
- **`ui/eq_window.rs`**: the equalizer's window (`EqWindow`), an `egui::Window` without a title bar on a `card_bg` frame, right-aligned under the bar's button and kept within the window when opened, dragged by its free space; inside `settings::equalizer` (the Sound page's `eq_head` and `bands`, shared) with its own `naming`. Not modal: the player's keys go on; the cross, Esc (not while a list or the name field takes it, or a modal is over it) or the button close it. The app sends `Player::set_dsp` and saves when `dsp` or `eq_presets` changed there. `METALAMP_EQ=1` opens it at start (GUI checks).
- **`library/watch.rs`**: `Watcher`, made anew with each scan (`App::start_scan`, and in `App::new` for the first): a "watch" thread waiting (`WaitForMultipleObjects`) on `FindFirstChangeNotificationW` of each library folder's subtree (names, sizes, writes; at most 63) and a stop event (set on drop; the thread closes it, or the watcher when no thread runs); a change sets a flag and wakes the app. `App::follow_folders` notes the time, asks for a frame when `QUIET` (3 s) has passed since the last change, then rescans unless a scan is under way (its end wakes the app). A folder that goes away (`FindNextChangeNotification` fails) is no longer waited on. Measured with a test copy: a file copied in or removed is in the index within 4 s; a copy's late notifications may cause one more rescan reading nothing.
- **`library/details.rs`**: everything a file says about itself, for the file info window: every field of its main tag (lofty's generic `Tag`, so ID3v2 frames lofty does not map are not shown) in the usual order of players and taggers (`ORDER`), then the rest; values of one key joined with "; ", track and disc numbers with their totals; the tags in the file (`ID3v2.3` from the file's header: lofty reads every version as 2.4), the pictures (type, format, pixels from the header only, bytes), the audio properties, an MP3's LAME delay and padding (`mp3gap`), and the cover (the tag's front cover, else its first picture, else the folder's, through `covers::decode`/`in_folder`, at most 400 px). `cargo test details_of_a_real_file -- --ignored --nocapture` with `METALAMP_SAMPLE` prints them.

A next track of another format waits for the ring to drain and opens the device anew. An output error (`AUDCLNT_E_DEVICE_INVALIDATED`, …) or a change of Windows' default device (checked once a second) reopens the output and seeks back to the position heard. Measured with `engine_crossfades` (2 s with 4 s left): the next heard after 2018 ms, at 12 ms of its own.

## Keys

The defaults of `keymap.rs` (changed on the settings' Keyboard shortcuts page; `App::run_key`):

Space or C: play/pause; X: play; V: stop; Shift+V: stop after the current track; Ctrl+Right or B: next; Ctrl+Left or Z: previous (Z X C V B); Shift+Left/Right, or Left/Right with the pointer over the title row or the player bar (`App::player_area`, the frame before's): 5 s back/forward; Ctrl+Up/Down, or Up/Down with the pointer over the title row or the player bar: volume; M: mute; R: repeat; S: shuffle; Ctrl+F: search; Ctrl+1…9: the whole library (1) or a view, in the order of the views' menu; Ctrl+M (or Esc in it): the mini player; Ctrl+T: over the other windows; Ctrl+O: open files (they replace the playlist; M3U/M3U8 are opened as their entries); Ctrl+Shift+O: add a folder; Alt+E: the playlist; I or Alt+3: the file info window (a click on the player bar's cover too); Ctrl+E: the tag editor (the playlist's selection when it has the keys, else the tracks' table's); Delete: remove from the playlist; Ctrl+R: read the folders again; F1: About; F5 or Ctrl+P: the settings window; the arrows, Page Up/Down, Home/End move in the pane last clicked, Enter plays; letters with the pointer over the artists go to an artist (the letter keys above wait then). Media keys (keyboards, headsets) come through the window's subclass, and while another window is active through Windows' media controls (`media_keys`: `always`/`window`/`off`, the General page); the taskbar button's thumbnail has Previous, Play/Pause and Next. The player's keys (Space, the letters, the arrows, Enter, Delete, I) wait while a text field has the focus; F1, F5, Ctrl+P, Ctrl+O, Ctrl+Shift+O, Ctrl+R, Ctrl+F, Alt+E and Alt+3 work then too. Outside the modals only a text field keeps the focus (`App::ui` drops a button's, which Tab gave). Files dropped on the window go to the playlist (played if nothing plays), folders into the library.

## Conventions

- Every user-visible string goes through `tr!("English", "Русский")` (`i18n.rs`); the language follows the Windows UI language (`i18n::system_lang`, `GetUserDefaultUILanguage`) unless chosen in the settings window (`i18n::LangChoice`, `system`/`en`/`ru` in the settings; applied in `App::new` before any text is made and at once when changed). Strings are built every frame, so nothing caches translated text. Log messages, CLI output and technical errors stay English.
- Persisted state (`settings.json`): `language` (`system`/`en`/`ru`), `check_updates`, `last_update_check` (Unix seconds), `window` (`normal`: `[left, top, right, bottom]` pixels, `maximized`), `album_view` (`grid`/`table`), `cover_size` (points), `artists_width`, `tracks_height` (points), `columns` (each table's widths by name: `artists`, `albums`, `tracks`), `sorts` (each table's `{column, descending}`; none: the library's order), `volume` (0-100), `mute`, `repeat` (`off`/`all`/`one`), `shuffle`, `playlist_visible`, `playlist_width`, `playlist_cover`, `playlist_current` (an index into `playlist.m3u8`), `playlist_position` (ms; `Player::position_to_keep`: the position while playing or paused, the place not yet taken up while stopped, else 0), `time_remaining` (the bar's time counts down), `bar_layout` (`full`/`classic`), `visualization` (`spectrum`/`waveform`/`scope`/`spectrogram`/`off`), `dsp` (`normalize`, `eq`, `preamp`, `bands` (10, dB), `enhancer`, `bass`/`clarity`/`width`/`warmth` 0–10, `limiter`), `eq_presets` (`{name, preamp, bands}`), `crossfade` (seconds, 0–12) and `crossfade_in_albums`, `window_layout` (`library`/`playlist`: the player and playlist layout, the early Winamp's: `App::ui` draws the playlist as the central panel, no library, no status line, `PlaylistView::no_library` leaves out its Go to items, Ctrl+F is its search (`focus_search`), Alt+E does nothing; `App::apply_layout` keeps the place of the layout left in its slot (`window` or `playlist_window`, `Settings::place`/`place_mut`), puts the other's back or `PLAYLIST_SIZE` (440×780, as narrow as it goes) centred where the window was, its least size (`Settings::min_size`, `PLAYLIST_MIN_SIZE` 440×400) to winit and to the subclass (`win::set_least`, as the mini player's: winit's comes a frame late), and `growing` until the window has it; `main` makes the window with the layout's sizes; the player bar is the narrow `BarLayout::Winamp` there (`App::bar_layout`; not offered in the settings: a display with the state icon and the time in the accent over the visualization (`winamp_display`, `winamp_visual_rect`), the title field (`NowPlaying::heading`, "N. Artist – Title", with the length), the facts, the speaker and the volume, the seek bar across, the transport and `toggles` under it, 156 points; `time` and `visual_display` are shared with the full layout); the playlist shows no cover and no cover button (`no_library`)), `playlist_window`, `visual_last` (the visualization the General page's switch and the `visualization` key turn back on; `Settings::set_visual`, `set_visual_on`, tested), `media_keys` (`always`/`window`/`off`), `keys` (the changes of the keymap, `keymap::Keymap::to_setting`), `tray` (minimize to the tray), `on_top` and `mini` (the title row's buttons, Ctrl+T and Ctrl+M; `ui/mini.rs`, `App::apply_modes`), `mini_rect` (the mini player's window rectangle, pixels, screen coordinates; none: the work area's bottom right corner), `theme` (`black`/`midnight`/`dark`/`steel`/`dimmed`/`sepia`/`light`), `accent` (`amber`/`blue`/`teal`/`green`/`orange`/`red`/`pink`/`purple`/`graphite` or `#RRGGBB`), `selection` and `playing` (`accent`/`grey`/`slate`/`blue`/`teal`/`purple` or `#RRGGBB`; `playing` also `bright`), `output_device` (an endpoint id; empty: Windows' default) with `output_device_name` (shown while it is absent), `views` (`[{name, icon, any, rules: [{field, op, value, to}]}]`, `library::filter`) and `view` (the name of the one in use, empty: the whole library), `library_folders` (paths; Ctrl+Shift+O or a folder dropped on the window adds one, a folder inside a listed one is not added, one holding listed ones replaces them; Ctrl+R rescans). The library index (`library.json`), the plays and ratings (`stats.json`), the loudness measurements (`loudness.json`), the playlist (`playlist.m3u8`) and the saved playlists (`playlists\<name>.m3u8`, `playlists.rs`: names as file names, Windows' forbidden letters as `_`; tested) sit next to `settings.json`.
- The version comes from `Cargo.toml` (`main::VERSION`, shown in About). Between releases it is the next version with `-dev`, the last number raised by one (after `0.1.0`, `0.1.1-dev`), and `build.rs` appends `git describe --tags --always` (`0.1.1-dev (v0.1.0-2-g4bd494d)`); a release version is shown as is. Release: drop `-dev`, commit `Version X.Y.Z`, tag `vX.Y.Z` (release.yml checks the tag against `Cargo.toml`), then set the next `-dev` version (`X.Y.(Z+1)-dev`).
- The release profile has `panic = "unwind"` and no console: other crates' parsers of the user's files (lofty's tags in the scan, the covers, the file info) run under `guard::catch`, so a panic on a damaged file is that file left out and logged (the scan would meet it at every start); any other panic shows a message box (`main::install_panic_hook`) and aborts. Unwinding made the exe 22 % larger (9.9 to 12.0 MB). `f32::clamp` panics when its bounds cross; sizes read from files may be 0.
- Commits in this repository end with a `Co-Authored-By:` trailer naming the Claude model doing the work, e.g. `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` (the user's decision; it overrides the global "no Co-Authored-By" rule for this repo only).
- GUI checks: the OpenGL client area cannot be captured with `PrintWindow` on an NVIDIA machine (the caption can, from a DPI-aware process); keys can be posted with `PostMessage(WM_KEYDOWN/WM_KEYUP)`, but each posted key reaches egui three times (seen in a trace of `raw_input_hook`: an arrow moved three rows), and posted `WM_CHAR` and Ctrl do not reach it (winit reads the keyboard's state), so typing and counts of steps are checked by the user; the screen can be captured with `CopyFromScreen` from a DPI-aware process (this machine's OpenGL area is captured). A launched window takes the focus: warn the user before launching test windows and before any simulated global mouse or keyboard input, and close test windows with `taskkill /PID` (WM_CLOSE, which saves the settings; `taskkill` sends nothing to a minimized window, so a minimized one is closed by posting WM_CLOSE to its windows, as `build.py`'s `post_close` does). A test copy runs apart from the installed one with a `metalamp.json` next to `target
elease\metalamp.exe` (portable mode: its own settings, index and covers; remove them after, the portable zip must not pick them up); `SendKeys` (SendInput) does reach egui, unlike posted messages, but simulated keys and clicks go to whatever window is in front (once the user's editor): do not simulate input; to look at a settings page, start the copy with `METALAMP_SETTINGS=sound:420` (`SettingsDialog::from_env`: the page and a scroll offset) and only capture the screen. A tooltip open when a modal opens by key stays until the pointer leaves its widget: egui keeps an open tooltip while the pointer is in its rect, whatever lies over it.
