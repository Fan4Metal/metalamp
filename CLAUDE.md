# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

MetalAMP is a Windows-only audio player written in Rust with egui/eframe 0.36 (glow), a replacement for Winamp whose main part is a Winamp-style media library: artists on the left, a grid of albums with their covers, the tracks below, the player bar on top, the playlist on the right, a status line. Playback is Windows' own: Media Foundation decodes (MP3, AAC/M4A, FLAC, WMA, WAV) and WASAPI plays. Priorities: start-up speed, a library that shows at once and stays smooth with thousands of tracks, gapless playback, no external runtime or DLLs. The implementation plan agreed with the user is `local/PLAN.md` (Russian, not in the repository); deferred work is in `TODO.md`. `README.md` / `README.ru.md` are the user-facing docs and must be kept in sync (both languages, cross-linked, formal tone, no imperatives).

The name is written `MetalAMP` wherever people read it (UI, window title, READMEs, installer, `%APPDATA%\MetalAMP`, `%LOCALAPPDATA%\Programs\MetalAMP`, `MetalAMP_<ver>_Setup.exe`) and `metalamp` wherever it is an identifier (Cargo package, `metalamp.exe`, the GitHub repo `Fan4Metal/metalamp`).

## Commands

```
uv run build.py                  # closes a metalamp.exe running from target\, then cargo build --release
cargo build --release            # target\release\metalamp.exe (fat LTO)
cargo test                       # unit tests (<what they cover>)
cargo clippy --all-targets       # must stay warning-free
python tools/make_release.py     # tests, release build, dist\MetalAMP_<ver>_Setup.exe (Inno Setup 6, tools/setup.iss) and _portable.zip
python tools/make_release.py --no-tests --install   # the same, then installs it silently over the installed copy
.\target\release\metalamp.exe --export-icon file.ico   # the app icon for the installer
python tools/icon_png.py         # images\icon.png (the README's icon) from the exe's icon
python tools/notices.py          # licenses\THIRD_PARTY_NOTICES.txt after the dependencies change (a test fails until then)
.\target\release\metalamp.exe --bench scan D:\Music   # a full scan without the index: walk, tags, grouping, index size, folders split into albums
.\target\release\metalamp.exe --bench gapless a.mp3 b.mp3   # what the decoder gives (trimmed) against each file's LAME tag
.\target\release\metalamp.exe --bench loudness a.mp3   # EBU R128 loudness, peak and the normalisation gain, with the time taken (ffmpeg -af ebur128 agrees to 0.1 LU)
RUST_LOG=metalamp=debug          # debug log (index and scan timings); METALAMP_SCAN_THREADS=n sets the tag readers (default min(cores, 8))
cargo test reads_a_real_file -- --ignored   # with METALAMP_SAMPLE=<an mp3>: lofty reads its tags
cargo test decoder_opens_sample -- --ignored   # METALAMP_SAMPLE: Media Foundation decodes it and seeks
cargo test engine_goes_on_without_a_gap -- --ignored --nocapture   # METALAMP_SAMPLE and the next file of its folder: plays ~3 s quietly on the default device
cargo test play_while_paused_plays -- --ignored --nocapture   # METALAMP_SAMPLE: a Play after a Pause plays (~2 s quietly)
```

Releases: pushing a tag `vX.Y.Z` runs `.github/workflows/release.yml`, which runs `make_release.py` and publishes both files; the tag must equal the version in `Cargo.toml`. Creating or pushing a tag publishes a public release, so do it only when the user asks. `tools/setup.iss` installs per user. `.cargo/config.toml` links the CRT statically, so no VCRUNTIME140.dll is needed. These scripts mirror those of disk_flashlight, qview, qrec and metalmd; keep them in step.

Trying a change: `cargo test` and `cargo clippy --all-targets`, then `uv run build.py` and run `target\release\metalamp.exe`; a test that plays sound should lower `volume` in `settings.json` first and put it back (it is the user's music on the user's speakers). When the change concerns the installed copy (installer, associations, portable mode) or the user runs the program all day, `python tools/make_release.py --no-tests --install` replaces the installed copy silently (it closes the running one first, so its settings are saved).

Toolchain: stable MSVC Rust plus VS 2022 Build Tools. In the Bash tool, `cargo` is not on PATH; prefix commands with `export PATH="$HOME/.cargo/bin:$PATH"`. A running `metalamp.exe` locks the release binary; `build.py` closes it first (WM_CLOSE via `taskkill`, so settings are saved; killed after 3 s). Heredocs containing Rust code break the Bash tool (lifetime apostrophes); write source files with the Write tool or a Python script.

## Architecture

- **`main.rs`**: arguments (`--export-icon`, `--register`/`--unregister` (named in the language of Windows), `--version`, `--help`, `--bench`, otherwise files: `normalize` fixes Explorer's `C:"` and makes them absolute; `instance::forward` hands them to a running copy; the release exe has no console, so the command line modes call `win::attach_parent_console`), the panic hook, `Settings::load`, the first `Scan` (the index read and the folders checked while eframe makes the window, so the first frame shows the library), `NativeOptions` (glow, `with_decorations(false)`, resizable, drag and drop, `DEFAULT_SIZE` 1280×800 points, `MIN_SIZE` 900×560, `centered` only without a saved place), `eframe::run_native`. eframe's `persistence` feature is off: the settings, the window's place among them, are the app's own JSON.
- **`app.rs`**: the eframe `App` (egui 0.36: `fn ui(&mut self, ui, frame)` with `egui::Panel::top/left/bottom(...).show(ui, ...)`, not the older `update(ctx)` / `SidePanel` API; `logic` runs every frame, also while minimised). `App::new` sets the language, `palette::apply` and egui's options (no keyboard zoom, Windows' double-click time, `line_scroll_speed` 100: a wheel notch scrolls 100 points, not egui's 40, as qview and metalmd), then, while the window is still hidden, the dark border, `win::round_corners` and the saved place (`win::place`: `SetWindowPlacement` with the saved `rcNormalPosition`, `SW_HIDE` or `SW_SHOWMAXIMIZED`; a maximized window is cloaked (`DWMWA_CLOAK`) until its first maximized frame, `uncloak`, at most 1 s: winit shows a window created maximized before it is painted, a white flash), and hooks the window (`win::hook_window`). `remember_place` reads `GetWindowPlacement` each frame and saves the settings in the background once the window has rested for 1 s; `on_exit`, the end of the session and sleep (`win::Hooked`) save at once.
- **`icon.rs`** draws the app icon procedurally with no dependencies (`ico` of BMP layers for `--export-icon`, `ico_of`, `bmp`); `build.rs` includes it via `#[path]` to write the `.ico` embedded by `winresource` (its 256 px layer as PNG through the `png` build dependency, as qview's, also for the file type icons: resources 101+) and `app_icon_{64,128,256}.rgba` into `OUT_DIR`; `main::embedded_icon` and `ui::app_icon` use those, so nothing is rasterised at start-up.
- **`settings.rs`**: JSON through serde as metalmd's (`%APPDATA%\MetalAMP\config\settings.json`; `#[serde(default)]`, so older files read with defaults and unknown fields are ignored; written as `.tmp` and renamed; `save_in_background` numbers the saves so the last asked for wins), or `metalamp.json` next to the exe when that file exists and can be written (portable mode, `settings::location`, decided once per run; the portable zip ships it empty). About shows which. `data_dir` is that folder: the library index, the playlist and the covers go there too. The window's place is `WindowPlace { normal, maximized }`: Windows' restored rectangle in pixels (work-area coordinates, kept also while maximized), so a window closed maximized comes back maximized and restores to its own size, not the screen's.
- **`update.rs`**: the opt-in update check (off by default, once a day at start-up, "Check now" in the settings window): `win::https_get` (WinHTTP) asks `api.github.com/repos/…/releases/latest`, `tag_name` is picked out of the JSON by hand, a newer release shows `ui::update_button` in the title row, opening the release page built from `CARGO_PKG_REPOSITORY`. `cargo test update -- --ignored` asks GitHub for real.
- **`caption.rs`**: `hwnd`, and `set_dark` (`DWMWA_USE_IMMERSIVE_DARK_MODE`) while the window is hidden and whenever the theme changes between dark and light.
- **`frameless.rs`** (metalmpv's without fullscreen): the window has no Windows frame but stays resizable for Windows (`WS_SIZEBOX`/`WS_MAXIMIZEBOX`: Aero Snap, Win+arrows, maximizing to the work area). No window region (qrec's way loses the DWM shadow): `win::round_corners` asks DWM for rounded corners (Windows 11; square on Windows 10). Strips along the edges (5 pt, corners 14 pt) start `ViewportCommand::BeginResize`; `drag_area` (`StartDrag`) leaves those strips alone, since a widget registered later covers an earlier one.
- **`palette.rs`**: every colour, as functions of the palette in use (`palette::text()`, not constants): `Theme` (listed from the darkest to the lightest, an order a test holds: black; midnight blue; dark graphite, the default; dimmed (softer cool greys); sepia (warm paper); light) and `Accent` (amber, the default, the icon's bolt; metalmpv's blue, teal, green, orange, red, pink, purple, graphite; and `Custom(0xRRGGBB)`, the last swatch, a colour wheel opening metalmpv's picker: saturation and brightness in a square, the hue in a bar, a field for the code in HEX, RGB or HSL (`ColourText`, switched by a click on its name; `Accent::typed` reads any of them, tested) and R, G, B fields; kept by name, `amber` or `#12AB9F`, an unknown one read as the default), both settings (`theme`, `accent`) on the General page (a list and metalmpv's round swatches, `accents`), applied at once (`palette::set` into a `RwLock`, `apply`, `caption::set_dark`); `Palette::of` mixes every accent's shades alike from its colour (the selection, the track playing, the spectrum; on a light ground a shade deeper; amber once kept a slate selection and a light blue track, which the user found out of place with it), `on_accent` (dark or white by luminance) for the Play button's glyph; a test checks every pair's contrasts (WCAG); and `apply` for egui's visuals (egui's dark or light as the base), scroll bars `ScrollStyle::thin` (always seen, 6 points taken: the lists lay their rows out in the viewport's width, not their rect's); the selection and the track playing in the lists are shades of the accent; the controls (the Play button, the seek bar, the toggles) keep the amber of the icon's bolt.
- **`ui/title.rs`**: the title row (metalmpv's): the icon (a click opens About, as F1; the family's "i" button is left out, the row is bare as Winamp's), the title, a newer release's button, minimise/maximise/close 46 points wide (`TitleCmd`); its free area drags the window, a double click maximizes.
- **`win.rs`**: `error_box` (user32 `MessageBoxW` declared by hand), `attach_parent_console`, `shell_open` (`ShellExecuteW`; eframe's `links` feature is off), `https_get`, `show_in_folder` (`SHOpenFolderAndSelectItems` on a thread with COM, declared by hand; `explorer /select` leaves the window behind the app's); from metalmpv `round_corners`, `cloak`, `placement`/`place`, `double_click_time` (egui assumes 0.3 s), and `hook_window`: a subclass (`SetWindowSubclass`) queuing media keys (`WM_KEYDOWN` with `VK_MEDIA_*`, which egui drops, and `WM_APPCOMMAND` from headsets and remotes), `WM_QUERYENDSESSION` and `PBT_APMSUSPEND` for `take_hooked`.
- **`library/`**: the media library. `Track` (path, size, mtime, title, artist, album artist, album, year, track, disc, genre, duration, bit rate, sample rate, channels, `has_cover`); `Library::new` groups tracks into albums by lower-case filed artist (album artist, else artist) and album title, **whatever their years** (Winamp's grouping: a compilation's tracks carry the years of their first release; the album's year is its earliest), tracks by disc, number, file name; artists by `format::natural_cmp` (case-blind, digits by value), their albums by year. `search` holds each track's lower-case words, `matches` needs every word of the query. `tags.rs` reads with lofty (`Probe` with properties and pictures: the whole ID3v2 tag is read anyway) and fills what the tag lacks from `Artist\(Year) Album\NN - Title.ext` (`split_number`, `split_year`). `index.rs`: `library.json` next to the settings, compact JSON with a `version`, ~350 bytes a track (1.7 MB for 4942). `scan.rs`: one thread per scan (`Scan`, dropped = cancelled): the index first (`ScanMsg::Loaded`), then `walk` (walkdir, `filetypes::is_audio`), unchanged files (same size and mtime) taken from the index, the rest read on a rayon pool of min(cores, 8) threads in chunks of 500 with a `Loaded` library after each (the first scan fills the view as it goes), progress at most 10 times a second, then grouped, the index saved when anything was read or removed, `ScanMsg::Done`. The UI only swaps the `Arc<Library>`.
  Measured on D:\Music (4942 MP3, 50 GB, a SATA HDD): walk 20 ms; tags cold 49 s (10 ms a file; 8 threads 7.3 ms a file against 11 ms for one on cold folders of the same disk), warm 161 ms; grouping 6-10 ms; the index read and grouped at start 12 ms, a rescan finding nothing changed 26 ms.
- **`ui/library.rs`**: the library view, as Winamp's: a bar (search field, Ctrl+F, Esc clears; albums as covers or as a table; the playlist shown or hidden; read the folders again, Ctrl+R; the folders' menu: remove one, add one), the artists on the left with "All" first, the albums at the top right, the tracks under them; strips between the panes move the borders (`artists_width`, `tracks_height`). The choice of artist and album is kept by name (lower-case name, `Album::key`), so it survives a new scan. A `View` (the artists, albums and tracks the search and the choice leave, each sorted by its table's column) is built only when the library's `Arc`, the search, the choice or a sort changed: 0.0-0.5 ms for 4942 tracks, shown in the status line as Winamp shows its query's time. Choosing an artist narrows the albums, an album the tracks; the arrow keys move in the pane last clicked (`Pane`) when no text field has the focus; letters typed with the pointer over the artists' pane (`pointer_over_artists`, decided by the app before its keys, which then leave the letters alone) go to the first artist starting with them, typed within 1 s of each other they add up, one letter again goes on to the next (`TypeAhead`, `type_ahead`, as Windows' lists; egui's text events, so Cyrillic too); Enter or a double click plays (an artist: its tracks once the view for it is built, `play_shown`; an album: its tracks; a track: the whole table from it, Winamp's way); the right button opens a menu (Play, Add to the playlist, Show in folder). The panes report `LibraryAction`s to the app. The album grid has the album table's header over it, which sorts it; cells of `cover_size` + 16 × `cover_size` + 48 points (the cover 96–256, `MIN_COVER`/`MAX_COVER`, 152 by default; Ctrl and the wheel over the grid step it by 16, and the right button on the bar's covers button opens `COVER_PRESETS` (112/152/208/256) and a slider; the thumbnails are 256 px, so the largest covers are a little upscaled on a scaled display), only the rows in sight painted.
- **`library/details.rs`**: everything a file says about itself, for the file info window: every field of its main tag (lofty's generic `Tag`, so ID3v2 frames lofty does not map are not shown) in the order of Winamp's File Info window (`ORDER`), then the rest; values of one key joined with "; ", track and disc numbers with their totals; the tags in the file (`ID3v2.3` from the file's header: lofty reads every version as 2.4), the pictures (type, format, pixels from the header only, bytes), the audio properties, an MP3's LAME delay and padding (`mp3gap`), and the cover (the tag's front cover, else its first picture, else the folder's, through `covers::decode`/`in_folder`, at most 400 px). `cargo test details_of_a_real_file -- --ignored --nocapture` with `METALAMP_SAMPLE` prints them.
- **`ui/info.rs`**: the file info window, as Winamp's File Info (an `egui::Modal` of 720 points with rounded corners): opened by a click on the player bar's cover (the track heard), I or Alt+3 (`App::info_path`: the playlist's selection when it was clicked last, else the tracks' table's, else the track heard or the playlist's current one) or "File info…" in the tracks' and the playlist's menus (`App::info_request`, opened at the end of the frame). A hero on top: the cover (150 points, rounded corners, `Image::paint_at`) beside the title, the artist, "album · year · genre" and chips with the format, length, bit rate, sample rate, channels and size (`chip`: a painted pill); then the sections "Tag" (the tags' names on the right; Winamp's fields in two `Grid` columns, `LEFT` and `RIGHT`, the comment and the tag's other fields under them; an empty field is a dash in the line colour; labels are `extend`ed, since a grid sizes its columns by the frame before, so a truncated label never got its room; TLEN is hidden, the chip has it; `field_name` names the keys Winamp and taggers show, the rest by lofty's name in words), "Lyrics" (USLT) and "File" (the path, the LAME tag, the pictures; "Show in folder" in its heading). The cross closes it (no button: the cross, Esc, Enter or a click outside). Below the hero everything is in one scroll area no taller than the screen allows (`min_scrolled_height` = `max_height`: a centred modal is placed by its size of the frame before, so an area that only took the room left froze at the height of the "Reading…" state), so a long tag never pushes the window off it. Esc, Enter, the cross or a click outside closes it; while it is open the app's keys wait. Files are read on one "info" thread that takes only the last path asked for meanwhile.
- **`ui/table.rs`**: the tables: `header_row` (a click sorts by a column, again the other way, `Sort`; a column's right edge dragged changes its width), rows of 20 points painted only where seen (`ScrollArea::show_viewport`), columns wider together than the table scrolled sideways (`ScrollArea::both`; the header is drawn after the rows with their offset), stripes, selection, the row playing in the accent, right-aligned text cut at its end when it does not fit; `click_select` (Ctrl toggles, Shift ranges from the anchor) and `key_move` (arrows, Page Up/Down, Home/End).
- **`covers.rs`**: album covers: a 256-pixel JPEG thumbnail per album in `covers\` next to the settings, named by an FNV-1a hash of the album's key and its first file's path and time (a changed file gets a new one); made from the folder's picture (`folder`, `cover`, `front`, `albumart`, any case: one small file, the quickest on a hard disk), else the first tagged track's front cover (lofty); an album without either gets an empty `.none` file. One worker thread, the album asked for last first (the cells in sight ask every frame); at most 256 textures (64 MB), the ones shown longest ago dropped. JPEG and PNG only, decoded within limits (8192 px, 256 MB).
- **`audio/`**: playback on the "audio" thread (COM MTA, Media Foundation started before anything holding MF objects, MMCSS "Pro Audio"). `decoder.rs`: the source reader (qrec's `trim::Sound`) on the first audio stream with a partial float media type, so Windows' own decoders do MP3, AAC (MP4, ADTS), FLAC, WMA, WAV; `seek` drops the samples before the time asked for. `output.rs`: `trait Output` (room, write with a gain, start/stop/reset, frames heard, `device_changed`) and `Wasapi` (shared mode on the default device or the one chosen in the settings (`open`'s `wanted`, an endpoint id; one not present is stood in for by the default, and `device_changed` goes back to it once it is present again); `AUTOCONVERTPCM | SRC_DEFAULT_QUALITY`, a 500 ms buffer of which only `WRITE_AHEAD` (150 ms) is kept written (the ring covers the disk; this covers the thread's scheduling), the position from `IAudioClock`, the gain through `IAudioStreamVolume`: the stream's own volume, which the audio engine applies where it mixes, so a change is heard within its 10 ms period and not after the 500 ms written ahead; not the session volume, which Windows shows in its mixer and remembers); a Winamp output plugin would be another `Output` (TODO.md). `list_devices` names the active output devices (`IMMDeviceEnumerator`, `PKEY_Device_FriendlyName`) on a thread with COM for the settings window. `mod.rs`: `Engine` (`Cmd`: Play, Preload, Pause, Resume, Stop, Seek, Device (the id; playing, it `recover`s onto it); `begin` (Play, and the track after a format change) clears a pause, `seek` and `recover` keep theirs; `Event`: Started, Ended, Failed; `Shared` atomics for the position, the duration and the gain). The decoded samples wait in a ring of twice the device buffer; when a track's decoder ends, the preloaded next one of the same format goes on into the same ring (gapless), and `Segment`s (where each track's first frame went among the frames written) against the device's clock tell which one is heard and its position. A next track of another format waits for the ring to drain and opens the device anew. An output error (`AUDCLNT_E_DEVICE_INVALIDATED`, …) or a change of Windows' default device (checked once a second) reopens the output and seeks back to the position heard. The thread polls every 10 ms while playing (250 ms idle). Measured: the second track of a preloaded pair starts at 10 ms of its own time (`engine_goes_on_without_a_gap`).
- **`audio/dsp/`**: the processing between the ring and the device, on the audio thread per block written (`Player::process`: the block cut at the `Segment` boundaries it spans, each piece with its track's gain, so the ring holds raw samples and a change of settings is heard within `WRITE_AHEAD` (150 ms) plus a poll; `Chain::process`, made in `begin` for the output's format, `configure`d by `Cmd::Dsp` with the filters' state kept; a wire while `DspSettings::active` is false): the track's loudness gain (`normalize`; `track_gain` brings the measured LUFS to `TARGET_LUFS` −18, capped so the peaks stay within 3 dB over the ceiling; slid over 300 ms, so a gain arriving mid-track is not a step), `eq.rs` (Winamp's ten bands at Q 1, peaking biquads per channel, a band at 0 dB skipped, the preamp; `PRESETS`: Flat first, then Winamp's 17 from its `winamp.q1`, the XMMS/VLC table scaled from its ±20 dB to Winamp's ±12), `enhancer.rs` (four amounts: bass = a low shelf at 100 Hz plus harmonics of the band under 120 Hz from a tanh fed at a levelled gain and kept to 90–500 Hz; clarity = tanh harmonics of what is over 4 kHz kept over 6 kHz plus a high shelf at 9 kHz; width = the side over 250 Hz raised up to twice; warmth = a blend with tanh at drive 2.5, unity at −12 dBFS), `limiter.rs` (5 ms look-ahead, a monotonic queue for the window's minimum gain, attack 1.2 ms, release 80 ms, ceiling −1 dBFS, a hard clip as the last resort) whenever anything is on. `biquad.rs` is the RBJ cookbook (transposed direct form II); `loudness.rs` the EBU R128 `Meter` (K-weighting derived for any rate as libebur128 does, 400 ms blocks every 100 ms, the −70 LUFS and −10 LU gates; a −23 dBFS sine reads −23.0 LUFS, and ffmpeg's `ebur128` agrees on real files). All tested with synthetic sines.
- **`loudness.rs`**: the tracks' measurements for normalisation: `loudness.json` next to the settings (`path: [LUFS, peak]`, version 1), a "loudness" thread with its own COM and Media Foundation decoding a file whole and metering it (about 0.5 s for a 4-minute MP3), asked by `Player::gain_for` for the track played and the one preloaded when their gain is not known (the engine plays them at 1 until `Cmd::Gain` arrives from `Player::poll`); normalisation turned on sends the gains of the tracks open. Tags' ReplayGain is not read (TODO.md).
- **`audio/mp3gap.rs`**: gapless MP3: the Xing/Info header of the first frame (after the ID3v2 tag) and the LAME tag after it (the encoder's delay and padding, 12 bits each 21 bytes into it; also a LAME tag without a Xing header). `Decoder` cuts an MP3 to its music: from sample `DECODER_OFFSET` (1153) + delay, `frames × 1152 − delay − padding` samples, and seeks in music time (the reader's time is the music's plus the offset); the duration shown is the music's. Measured with `--bench gapless` on 41 tagged files of D:\Music (all LAME, delay 576): Media Foundation gives `frames × 1152 + 624` samples (the Info frame decoded as silence, 528 of its own 529-sample delay left out at the start), at least 624 exact zeros at the start, and exactly `padding − 529` zeros at the end, so the music starts at 1153 + delay; trimmed, it gives exactly the tag's music length. A tag without a frame count or with a delay or padding past 4000 (a damaged one, seen as 0x555 twice) is not used: the file plays whole.
- **`player.rs`**: joins the playlist and the engine: tokens per `Play`/`Preload` mapped to playlist entries (each with its loudness gain, `gain_for`; `set_dsp` passes the settings on) (so repeat one restarts as news), `refresh_preload` after each start and each change of the list, repeat or shuffle; a failed track is skipped (a failed preload: the one after it is preloaded instead), and after as many failures in a row as the list is long, it stops. The volume is a gain of (v/100)², given to the output (`Output::set_gain` before every write), so a change is heard at once. Previous goes to the start of the track past its first 3 s.
- **`queue.rs`**: the playlist (after metalmpv's `playlist.rs`): entries with ids of their own, the current one, `Repeat` (off, all, one), shuffle as a random order of play with the current entry first (xorshift), `after`/`before`, `add`/`remove`/`move_to`, M3U8 written as Winamp does (UTF-8 without a BOM, CRLF, `#EXTINF`) and read (`m3u_paths`).
- **`ui/player_bar.rs`**: the bar under the title row in one of two layouts (`BarLayout`, a setting; `height`): `Winamp` (118 points), laid out as Winamp's main window: the player in `PLAYER_WIDTH` (520) on the left, the spectrum analyzer in the room right of it (`analyzer_rect`, left out under 60 points). The player: the time in large monospace digits (the largest of three sizes that fits `TIME_WIDTH`; a click toggles `time_remaining` in the settings, shown as `-m:ss`), the cover (a click opens the file info window), the title, the artist and album, and `facts` (bit rate, sample rate, channels of the library's track, `format::sample_rate`/`channels`, shared with the file info's chips); the seek bar with the length at its end (seeks when let go, the time under the pointer as a tip); Previous, Play/Pause (round, in the accent), Stop, Next; shuffle, repeat, the mute button and the volume slider (a click or drag sets it; the wheel anywhere over the title row and the bar steps it by 5, `App::ui`); `Classic` (76 points), the bar before it: one row of the buttons, the cover and the names, the toggles and the volume, the seek bar across the bottom with the times at its ends. Both are built from the same pieces (`transport`, `volume_and_toggles`, `seek_bar`, `cover_button`). Its free space drags the window.
- **`ui/spectrum.rs`**: the analyzer: `Analyzer::feed` takes the `N` (2048) mono frames heard now (`App::player_bar` gets them from `Player::heard_samples`, the engine's `vis::Tap`), Hann window, an own radix-2 FFT (no dependency), bands log-spaced 40 Hz to 16 kHz (as many as fit at `BAR_PITCH` 7 points, a band narrower than a bin interpolated between its two bins), each the loudest bin in dB of full scale, a full bar at `TOP_DB` (-6), the floor `RANGE_DB` (60) under it, with a tilt of 3 dB per octave about 500 Hz (music is pink); bars fall the whole height in 0.45 s, peaks hold 0.5 s then fall with a growing speed; painted as one `Mesh` (amber to pale gold by height, `palette::SPECTRUM_*`). The app repaints every 20 ms while playing or while anything shows (`active`); paused, the heard window stays the same, so the bars freeze; stopped, the tap is cleared and they fall.
- **`audio/vis.rs`**: `Tap` behind `Shared::vis` (a mutex): the frames written to the device, mixed to mono, in a ring of 2^18 by their index in the device's count, and the device's clock (`set_heard` each step), so `latest(n)` gives the `n` frames heard at this moment, half a second behind what was written. Cleared by `stop` and `begin`; a push at an index other than the end starts the count over.
- **`ui/playlist.rs`**: the playlist on the right (an egui right panel, resizable, `playlist_width`; Alt+E or the bar's button shows or hides it): Clear, a search field (every word in "Artist – Title"), rows "N. Artist – Title" with the length, the entry playing in the accent, selection as in the tables, rows dragged to another place (a line shows the slot; `Queue::move_to`), Delete removes (the entry heard removed: what came after it plays), Enter or a double click plays, a context menu (Play, Remove, Show in folder, Clear), the total length and a button that scrolls to the entry playing; under the list the cover of the track heard (`playlist_cover`; the bar's picture button or the cover's own menu hides it; as wide as the panel up to 360 points, left out when fewer than 4 rows would stay; a click opens the file info), the library's thumbnail through `App::playing_cover`. A press inside the playlist gives it the keys, a press elsewhere gives them back to the library's panes. `App::remember_playlist` writes `playlist.m3u8` next to the settings (on a thread, `.tmp` and renamed) whenever the list changed, and the current entry is the `playlist_current` setting; `load_playlist` reads them at start (not playing).
- **`filetypes.rs`**: the types MetalAMP plays and registers (`FILE_TYPES`: MP3, FLAC, M4A/AAC, WAV, WMA as audio, M3U/M3U8 as playlists; each with its label, Explorer's type names in both languages and metalmpv's colours), `AUDIO_EXTENSIONS` (the library's files, any case) and `icon_id` (resource 101 + the type's place: new types go at the end, Explorer remembers the IDs). Dependency-free, included by `build.rs`.
- **`type_icon.rs`** (metalmpv's, unchanged): the file types' icons, a white page with a note (audio) or a list (playlist) and the label on a band in a pixel font, drawn at every size; only `build.rs` uses it.
- **`assoc.rs`** (metalmpv's, the settings page's parts left out): `--register`/`--unregister` for the installer, per user under HKCU: a ProgID `metalamp.<id>` per type with its name, icon (`"metalamp.exe",-<id>`) and open command, the ProgID in each extension's `OpenWithProgids`, `Applications\metalamp.exe`, `Software\MetalAMP\Capabilities` listed in `RegisteredApplications` (Settings → Default apps); an extension no program claims gets the ProgID as its default; Explorer's own `*_auto_file` ProgIDs that run this exe get the type's icon and name. `UserChoice` is never written. `--unregister` leaves another copy's registration alone. Tested in a scratch key.
- **`instance.rs`** (metalmpv's, from qview): one window per exe: a mutex `Local\metalamp.<hash of the exe path>` and a message-only window of that class taking a start's paths in one `WM_COPYDATA` (NUL-separated, `dwData` = `0x6d616d70`); the second start brings the first window forward and exits (measured: 124 ms). `App::take_handed_over`: the files replace the playlist and play, those within 300 ms of the last ones (the rest of an Explorer selection, one process per file) are added. Files on the command line of the first start play the same way.
- **`taskbar.rs`** (metalmpv's, the tooltips naming tracks): the taskbar button through `ITaskbarList3`, declared by hand (COM is up on the UI thread from winit's `OleInitialize`): the position as progress per mille (`TBPF_PAUSED` yellow when paused, none when stopped) and three thumbnail buttons (Previous, Play/Pause, Next; disabled when there is no previous or next, `App::has_previous`: a track before or past 3 s into this one), whose icons are drawn here (`glyph_pixels`, 4×4 samples, the small icon size at the window's DPI) into `CreateIconIndirect`, made anew for another DPI or language; nothing is called before `TaskbarButtonCreated` (a registered message `win::hook_window` turns into `Hooked::TaskbarButton`; Explorer sends it again after a restart); clicks come as `WM_COMMAND`/`THBN_CLICKED`, `Hooked::Thumb(id)`; both let through UIPI for an elevated copy. `App::show_on_taskbar` (in `logic`) passes what changed.
- **`smtc.rs`** (metalmpv's): Windows' media controls (`SystemMediaTransportControls`, WinRT declared by hand, `combase` as `raw-dylib`): `GetForWindow`, Play/Pause/Stop on, Previous/Next as the playlist allows, the status, the title and the artist as music in Windows' flyout (`App::show_in_media_controls`); the ButtonPressed handler is an agile COM object (`Handler`, called on a thread of Windows') that queues `win::hook_media`. The media keys work without the focus while `settings.media_keys` is `always` (`App::follow_media_keys` makes or drops the controls; `window`: the window's own keys only; `off`: `win::set_media_keys(false)`, the keys go on through `DefWindowProc`, which winit skips); a press that comes both as the window's key and from the controls counts once (`app::same_press`, 300 ms, Play/Pause/PlayPause one button; `win::Via`). Dropped, the controls are closed and disabled first, else Windows kept the player as the session the keys go to. `cargo test media_controls -- --ignored` gets the controls of a hidden window.
- **`format.rs`**: track times, the library's length as Winamp's status line (`15 days+16:40:20` / `15 дн.+16:40:20`), sizes in binary units (`49.02 GB` / `49,02 ГБ`), `natural_cmp`.
- **`bench.rs`**: `--bench scan <folder>…` (see Commands).
- **`ui/status.rs`**: the status line: tracks, length, size; the scan's progress on the right.
- **`ui/`**: `app_icon`, toolbar buttons with a painted icon (`icon_button`), `update_button`, `close_cross`, `double_clicked`; `App::raw_input_hook` holds the right button's press back until it is let go and gives both to egui at the release, so a context menu opens even when the mouse moved while the button was down (egui's click allows 6 points and 0.8 s; qview's way); `ui/about.rs` the About modal (the language and the update check are not there: in the settings window, as metalmpv's); `ui/settings.rs` the settings window (F5 as metalmpv's, Ctrl+P as Winamp's Preferences, or the gear at the right end of the library's bar, `LibraryAction::Settings`): metalmpv's layout, a modal of 820×560 (metalmpv's; smaller in a smaller window, `modal_size`) with the categories in a darker column on the left (General: the language, `bar_layout`; Sound: the output device, listed by `output::list_devices` when the window opens, then the loudness switch, the equalizer as metalmpv's (`eq_head`: the switch, Winamp's presets and the user's `eq_presets` under "Mine" in one list, the one the sliders stand at named, a plus that opens `name_row` (a field, a tick, a cross; Enter saves, Esc gives up; at most 20, the oldest dropped) and a bin; `bands`: the preamp's column, a ±12 dB scale, a vertical slider per band with its gain over it and its frequency and a reset arrow under it, the 0 dB line and a Catmull-Rom curve through the knobs (`smooth`) drawn under them, greyed while off; `tool`: the small icon button) and the enhancer's four amounts (`amount`), applied live (`Changed::dsp` → `Player::set_dsp`); Updates: the check, as About had it), Reset and Close under them, the page in cards of `row`s; it edits `Settings` in place and returns `Changed` (`device`: the app sends it to the player; `any`: save); `ui/start.rs` the start screen while the library has no folder (icon, name, version, one line on how to begin); `ui/licenses.rs` the Licenses window (metalmpv's, from About's **Licenses…**, shown in its place): two parts, the program's MIT `LICENSE` and `licenses/THIRD_PARTY_NOTICES.txt` (both `include_str!`; the notices of the 162 crates compiled in and egui's fonts, written by `tools/notices.py` with Cargo.lock's FNV-1a hash, which `licenses::tests` checks; the installer and the portable zip ship the file too), the lines wrapped at words to the width (`wrap`) for `show_rows`.
- **`ui/icons.rs`**: the painted icons shared by the family (the default fonts lack many symbols), on a 14-point grid with 1.3-point lines; `Shuffle`, `Repeat`, `RepeatOne` (from metalmpv), `Refresh` (the common sync sign the user gave as the model: two arcs of 122° ending in solid triangles whose flat bases straddle the ring at three and nine o'clock, unlike the single arc of the turns), `Image` (a frame with a sun and hills) and `Library` (three filled spines, the last leaning on the second; the folders' menu; outlined spines kept no room inside at 14 points, and bands cut across them read as the dots of an "i") were added here and copied back to the skill's catalogue. - **`icon.rs`** (the drawing): a yellow lightning bolt (a polygon, light at the top and amber at the bottom) with a darker edge, so it keeps its shape on a light taskbar, a lit upper-left side and a soft shadow; layers of 24 px and less get an edge of one pixel and no lit side. `sample(x, y, px)` smooths edges over one pixel of the layer (a signed distance to the polygon).


## Keys

Space or C: play/pause; X: play; V: stop; Ctrl+Right or B: next; Ctrl+Left or Z: previous (Winamp's Z X C V B); Shift+Left/Right: 5 s back/forward; Ctrl+Up/Down: volume; M: mute; R: repeat; S: shuffle; Ctrl+F: search; Ctrl+O: open files (they replace the playlist; M3U/M3U8 are opened as their entries); Ctrl+Shift+O: add a folder; Alt+E: the playlist; I or Alt+3: the file info window (a click on the player bar's cover too); Delete: remove from the playlist; Ctrl+R: read the folders again; F1: About; F5 or Ctrl+P: the settings window; the arrows, Page Up/Down, Home/End move in the pane last clicked, Enter plays; letters with the pointer over the artists go to an artist (the letter keys above wait then). Media keys (keyboards, headsets) come through the window's subclass, and while another window is active through Windows' media controls (`media_keys`: `always`/`window`/`off`, the General page); the taskbar button's thumbnail has Previous, Play/Pause and Next. All but F1 wait while a text field has the focus. Files dropped on the window go to the playlist (played if nothing plays), folders into the library.

## Conventions

- Every user-visible string goes through `tr!("English", "Русский")` (`i18n.rs`); the language follows the Windows UI language (`i18n::system_lang`, `GetUserDefaultUILanguage`) unless chosen in the settings window (`i18n::LangChoice`, `system`/`en`/`ru` in the settings; applied in `App::new` before any text is made and at once when changed). Strings are built every frame, so nothing caches translated text. Log messages, CLI output and technical errors stay English.
- Persisted state (`settings.json`): `language` (`system`/`en`/`ru`), `check_updates`, `last_update_check` (Unix seconds), `window` (`normal`: `[left, top, right, bottom]` pixels, `maximized`), `album_view` (`grid`/`table`), `cover_size` (points), `artists_width`, `tracks_height` (points), `columns` (each table's widths by name: `artists`, `albums`, `tracks`), `sorts` (each table's `{column, descending}`; none: the library's order), `volume` (0-100), `mute`, `repeat` (`off`/`all`/`one`), `shuffle`, `playlist_visible`, `playlist_width`, `playlist_cover`, `playlist_current` (an index into `playlist.m3u8`), `time_remaining` (the bar's time counts down), `bar_layout` (`winamp`/`classic`), `dsp` (`normalize`, `eq`, `preamp`, `bands` (10, dB), `enhancer`, `bass`/`clarity`/`width`/`warmth` 0–10), `eq_presets` (`{name, preamp, bands}`), `media_keys` (`always`/`window`/`off`), `theme` (`black`/`midnight`/`dark`/`dimmed`/`sepia`/`light`), `accent` (`amber`/`blue`/`teal`/`green`/`orange`/`red`/`pink`/`purple`/`graphite` or `#RRGGBB`), `output_device` (an endpoint id; empty: Windows' default) with `output_device_name` (shown while it is absent), `library_folders` (paths; Ctrl+Shift+O or a folder dropped on the window adds one, a folder inside a listed one is not added, one holding listed ones replaces them; Ctrl+R rescans). The library index (`library.json`) sits next to `settings.json`.
- The version comes from `Cargo.toml` (`main::VERSION`, shown in About). Between releases it is the next version with `-dev`, the last number raised by one (after `0.1.0`, `0.1.1-dev`), and `build.rs` appends `git describe --tags --always` (`0.1.1-dev (v0.1.0-2-g4bd494d)`); a release version is shown as is. Release: drop `-dev`, commit `Version X.Y.Z`, tag `vX.Y.Z` (release.yml checks the tag against `Cargo.toml`), then set the next `-dev` version (`X.Y.(Z+1)-dev`).
- The release profile has `panic = "abort"` and no console: a panic shows a message box (`main::install_panic_hook`) and ends the program. `f32::clamp` panics when its bounds cross; sizes read from files may be 0.
- Commits in this repository end with a `Co-Authored-By:` trailer naming the Claude model doing the work, e.g. `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` (the user's decision; it overrides the global "no Co-Authored-By" rule for this repo only).
- GUI checks: the OpenGL client area cannot be captured with `PrintWindow` on an NVIDIA machine (the caption can, from a DPI-aware process); keys can be posted with `PostMessage(WM_KEYDOWN/WM_KEYUP)`, but each posted key reaches egui three times (seen in a trace of `raw_input_hook`: an arrow moved three rows), and posted `WM_CHAR` and Ctrl do not reach it (winit reads the keyboard's state), so typing and counts of steps are checked by the user; the screen can be captured with `CopyFromScreen` from a DPI-aware process (this machine's OpenGL area is captured). A launched window takes the focus: warn the user before launching test windows and before any simulated global mouse or keyboard input, and close test windows with `taskkill /PID` (WM_CLOSE, which saves the settings). A test copy runs apart from the installed one with a `metalamp.json` next to `target
elease\metalamp.exe` (portable mode: its own settings, index and covers; remove them after, the portable zip must not pick them up); `SendKeys` (SendInput) does reach egui, unlike posted messages, but simulated keys and clicks go to whatever window is in front (once the user's editor): do not simulate input; to look at a settings page, start the copy with `METALAMP_SETTINGS=sound:420` (`SettingsDialog::from_env`: the page and a scroll offset) and only capture the screen. A tooltip open when a modal opens by key stays until the pointer leaves its widget: egui keeps an open tooltip while the pointer is in its rect, whatever lies over it.
